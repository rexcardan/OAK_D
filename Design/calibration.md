# Camera Calibration Process

This document outlines the steps required to calibrate the OAK-D camera using the `qacam` library and a printed calibration pattern (e.g., the ArUco grid generated by `generate_calib_pattern.py`). Accurate calibration is crucial for obtaining reliable 3D measurements and pose estimations.

## 1. Prerequisites

Before starting the calibration, ensure you have the following:

1.  **Printed Calibration Pattern:** The ArUco grid pattern (e.g., `my_calibration_pattern.png`) printed accurately without scaling (100% / Actual Size) on a flat, rigid surface.
2.  **Measured Pattern Dimensions:** You *must* have carefully measured the following dimensions from the *printed* pattern using a precise ruler or caliper:
    *   **Marker Size (meters):** The side length of a single square black marker.
    *   **Marker Separation (meters):** The distance between adjacent markers (e.g., from the bottom edge of one marker to the top edge of the marker below it).
3.  **Camera Connected:** The OAK-D camera must be connected to your computer.
4.  **Environment Setup:** A well-lit area where you can move the printed pattern relative to the camera (or vice-versa) to capture views from various angles and distances.

## 2. Calibration Procedure Overview

The calibration process involves capturing multiple images of the known pattern from different viewpoints. The `qacam` library (specifically the `Calibration` class) uses these images and the known physical dimensions of the pattern to calculate the camera's intrinsic parameters (focal length, principal point, distortion coefficients) and potentially extrinsic parameters relative to the pattern if needed later.

## 3. Running the Calibration

Currently, the `qacam.Calibration.calibrate()` method contains placeholder logic. A dedicated script is needed to orchestrate the calibration image capture and processing.

**Proposed Script (`calibrate_camera.py` - *To be created*):**

A script, let's call it `calibrate_camera.py`, should be created in the project root. This script would perform the following actions:

1.  **Import necessary modules:** `CameraHandler`, `Calibration`, `cv2`.
2.  **Prompt for Measured Dimensions:** Ask the user to input the measured `marker_size_m` and `marker_separation_m` obtained in the prerequisites.
3.  **Initialize `CameraHandler` and `Calibration`:** Create instances of these classes.
4.  **Image Capture Loop:**
    *   Start displaying the live feed from the camera (`CameraHandler.get_rgbd_frames()`).
    *   Instruct the user to position the pattern in the camera's view.
    *   When the user indicates (e.g., by pressing a key), attempt to detect the pattern in the current frame (`cv2.aruco.detectMarkers`).
    *   If the pattern is detected successfully:
        *   Store the detected 2D image points (corner coordinates).
        *   Store the corresponding 3D object points (calculated based on the known pattern layout and measured dimensions).
        *   Provide visual feedback (e.g., draw detected corners on the displayed image).
        *   Increment a counter for successfully captured views.
    *   Instruct the user to move the pattern to a *different position and orientation* relative to the camera (varying distance, angle, tilt). It's crucial to capture diverse views covering different parts of the camera's field of view, especially near the edges.
    *   Repeat until a sufficient number of views (e.g., 20-30) are captured.
5.  **Calculate Calibration Parameters:** Once enough views are collected, call `cv2.calibrateCamera()` using the stored object points and image points.
6.  **Save Parameters:** If `cv2.calibrateCamera()` is successful, take the returned camera matrix and distortion coefficients and save them using the `Calibration.save_parameters()` method.

## 4. Calibration File Storage

*   **Default Location:** By default, the `Calibration` class saves the calculated parameters to a file named `calibration_params.yaml` in the project's root directory (`c:/Users/rexca/source/repos/OAK_D`).
*   **Custom Location:** The filename can be customized when initializing the `Calibration` object (e.g., `calibrator = Calibration(handler, params_file="my_custom_params.yaml")`). The `main.py` script currently uses the default filename.

## 5. Automatic Usage by the Library

*   **Loading:** When an instance of the `Calibration` class is created (like in `main.py`), it automatically attempts to load parameters from the specified file (`calibration_params.yaml` by default) using its `load_parameters()` method during initialization (`__init__`).
*   **Usage:** If parameters are loaded successfully, they are stored within the `Calibration` instance. Other modules, like `Tracking`, receive the `Calibration` instance during their own initialization. The `Tracking` module then accesses the loaded parameters (`camera_matrix`, `distortion_coefficients`) from the `Calibration` instance when performing pose estimation (`_estimate_pose` method).

Therefore, as long as the `calibration_params.yaml` file exists in the expected location when you run `main.py` (or any script that initializes `Calibration` and `Tracking` correctly), the calibration data **will be used automatically**.
